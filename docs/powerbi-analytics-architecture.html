1. Executive Summary

PlainLedger Platform: A multi-tenant financial reporting platform that connects to accounting software (QuickBooks, Xero, Sage), stores data in an AWS S3 data lake, and provides embedded Power BI analytics - all secured through Keycloak SSO with organization and business unit level access control.

Key Architecture Decisions

Q

One OAuth Token Per Connection

Each QuickBooks company requires its own OAuth token. Tokens are stored securely and associated with organization + business unit.

S3

Tenant-Partitioned Data Lake

S3 data is partitioned by organization_id/business_unit_id for efficient querying and data isolation.

🔐

Single Identity (Keycloak)

Users authenticate only via Keycloak. No Azure AD accounts. One Power BI service principal owns all content.

📈

Server-Side RLS

Power BI Row-Level Security enforced server-side. Users cannot bypass data filters even with browser dev tools.

What This Architecture Provides

  • ✓ Single sign-on via Keycloak (users don't need Microsoft accounts)
  • ✓ Flat licensing cost (scales by capacity, not users)
  • ✓ Multi-level filtering (Organization + Business Unit)
  • ✓ Server-side security (cannot be bypassed)
  • ✓ Full white-label capability
  • ✓ Flexible integration management (CPA-managed or customer self-service)
  • ✓ Granular permissions for data source connections per org/BU

What This Is NOT

  • ✗ Users do NOT need Microsoft/Azure AD accounts
  • ✗ We do NOT pay per-user Power BI licenses
  • ✗ Data is NOT filtered client-side (secure)
  • ✗ No identity synchronization between Keycloak and Azure AD

Onboarding Scenarios

PlainLedger CPA performs all integrations

  • Customer provides QuickBooks admin credentials to CPA
  • CPA team connects and configures all data sources
  • Customer users only have viewer/analyst access
  • Best for: Small businesses, hands-off clients

Scenario B: Self-Service

Customer manages their own integrations

Security Note: The manage:connections permission is marked as Critical because it grants access to initiate OAuth flows and store credentials. Only trusted users (IT admins, CFOs, controllers) should be assigned this permission. All connection changes are logged in the audit trail.

3. OAuth Token Management

Connection Flow (User Perspective)

Step 1: User Logs into PlainLedger

Via Keycloak SSO

User authenticates with their Keycloak credentials (email/password, Google SSO, or Microsoft SSO).

Step 2: Navigate to Connections

Select business unit

User selects which business unit they want to connect (e.g., "ACME Finance").

Step 3: Click "Connect QuickBooks"

OAuth redirect

User is redirected to Intuit's OAuth page. They log in with their QuickBooks credentials and select which QBO company to authorize.

Step 4: Authorization Granted

Token stored

PlainLedger receives OAuth tokens and stores them encrypted in the database, associated with the organization + business unit.

Step 5: Initial Sync

Data pulled to S3

PlainLedger immediately syncs all historical data from QuickBooks to the S3 data lake.

Token Lifecycle Management

Token Type Validity Refresh Strategy Expiry Handling
Access Token 1 hour Auto-refresh before each API call if expired Use refresh token to get new access token
Refresh Token 100 days (rolling) Extended each time used Prompt user to reconnect if not used in 100 days
Refresh Token (Max) 5 years absolute Cannot be extended past max Email notification 30 days before; reconnect required
Important (2025 Policy Change): QuickBooks refresh tokens now have a maximum 5-year lifetime. PlainLedger must track expiration dates and prompt users to reauthorize before tokens expire. Automated email reminders are sent 30 days and 7 days before expiration.

4. S3 Data Lake Architecture

Medallion Architecture (Bronze/Silver/Gold)

BRONZE LAYER

Raw Data

Exact copy of data from QuickBooks API responses. No transformations. JSON format.

  • Immutable audit trail
  • Partitioned by sync date
  • 90-day retention → Glacier
SILVER LAYER

Cleaned Data

Validated, deduplicated, standardized schema. Parquet format with Snappy compression.

  • Consistent data types
  • Null handling
  • Schema enforcement
GOLD LAYER

Analytics-Ready

Aggregated, enriched, optimized for Power BI. Parquet format, pre-computed metrics.

  • Partitioned by org/BU
  • Optimized for queries
  • Power BI data source

Row-Level Security (Server-Side)

Power BI RLS filters data based on the identity passed in the embed token. This is enforced by Power BI servers - users cannot bypass it.

// PlainLedger API generates embed token with RLS identity async generateEmbedToken(user: KeycloakUser, reportId: string) { // 1. Extract from Keycloak JWT const { organization_id, business_units, role } = user; // 2. Determine business unit access const customData = role === 'admin' ? 'ALL' // Admin sees all BUs in their org : business_units.join('|'); // Others see specific BUs // 3. Generate token with RLS identity const token = await powerBI.generateToken({ reportId: reportId, identities: [{ username: organization_id, // Used by RLS filter roles: ['TenantFilter'], // Power BI RLS role datasets: [datasetId], customData: customData // Business unit filter }] }); // Power BI server enforces: [organization_id] = "acme-corp" // User CANNOT bypass this filter return token; }

Security Comparison: Why Server-Side RLS

Aspect Client-Side Filters (Rejected) RLS with Embed Identity (Chosen)
Where enforced Browser JavaScript Power BI Server
Can user bypass? Yes - via dev tools No - server enforced
Data export Risk of unfiltered data Exports respect RLS filters
Audit trail Platform logs only Platform + Power BI audit logs
Security Guarantee: Even if a user modifies JavaScript or inspects network traffic, they cannot see data outside their organization. The filter is enforced by Power BI's servers before any data is sent to the browser.

E. Cost Optimization Recommendations

1. Implement Delta Sync

Only transfer changed data to Azure. Reduces egress costs by ~95%.

Implementation: Track last sync timestamp, use CDC patterns.

2. Compress Data

Parquet with Snappy compression is 70-90% smaller than JSON.

Savings: 3-5x reduction in transfer volume.

3. S3 Intelligent Tiering

Move infrequently accessed Bronze data to cheaper storage classes.

Savings: Up to 40% on storage costs.

4. Monitor Costs

Set up AWS Cost Alerts for egress charges.

Action: Alert at 50%, 75%, 100% of budget.
